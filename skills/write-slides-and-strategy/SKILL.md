# Write slides and strategy

1. Read the shared [context gate](../contextual-writing/references/context-gate.md), [evidence rules](../contextual-writing/references/evidence-and-preservation.md), and [language rules](../contextual-writing/references/language-and-register.md).
2. Read [slides and strategy](references/slides-and-strategy.md).
3. Resolve audience, decision, presentation setting, available time, speaker-led or sendable mode, evidence, template, and output format.
4. Ask only missing decision-critical fields from [the deck intake](assets/deck-intake.md).
5. Build the governing question and answer before slide sequence. Give each slide one decision-useful message and make its body prove the headline.
6. Separate supplied facts, researched evidence, assumptions, calculations, and open fields. Never invent traction, customers, economics, funding needs, market proof, or customer commitments.
7. When the user requests an editable PowerPoint or Google Slides artifact, keep this skill as content owner and check whether a presentation-authoring skill is available. If available, use it for authoring, template handling, rendering, and visual QA. If unavailable, provide the completed source-backed slide content in the requested fallback format and state that an editable deck could not be produced without an authoring capability. Never claim an artifact or plugin exists without verification.
8. For external, assessed, or hard-limit slides and scripts, apply the shared [submission-readiness gate](../contextual-writing/references/submission-readiness.md). Keep internal uncertainty and account notes outside recipient-visible content unless they are explicitly requested as source or appendix material.
9. Return the finished requested artifact or slide content, not only a planning outline.
