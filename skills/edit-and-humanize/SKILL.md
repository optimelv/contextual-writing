# Edit and humanize

Hard stop: do not rewrite operative legal, contractual, regulatory, policy, specification, or compliance wording into replacement text. Route first to [professional communication](../write-professional-communication/SKILL.md), reproduce the original unchanged under `Original operative wording`, and offer only a separately labeled non-operative plain-language explanation unless an authorized domain owner supplies or approves replacement wording.

1. Read the shared [evidence rules](../contextual-writing/references/evidence-and-preservation.md), [language rules](../contextual-writing/references/language-and-register.md), [humanizing and QA](../contextual-writing/references/humanizing-and-qa.md), [submission readiness](../contextual-writing/references/submission-readiness.md), and [style calibration](../contextual-writing/references/style-calibration.md) when samples exist.
2. Read [editing modes](references/editing-modes.md).
3. Identify the requested mode, audience, language, register, protected material, format, and change budget from context. Ask only when ambiguity would materially change the edit.
4. Build claim, persona, and structure locks from the original.
5. Diagnose actual problems. Do not use isolated words or punctuation as authorship evidence.
6. Default to the smallest edit that improves the stated outcome. Preserve clean passages and allow a null edit.
7. Compare the final text with the original, not only with the previous pass.
8. For material factual edits, run the shared claim and style guards. Treat all findings as review prompts and complete a semantic comparison.
9. If the edited result is recipient-visible or hard-limited, run the submission-readiness gate after the final edit. Keep review commentary and internal drafting notes outside the submitted copy; recount with the destination's own counter when available.

For a CV, legal message, research report, sales message, or slide deck, use the matching owner skill first and load this as its editing layer.
